# ADR 0004: Test Emulator Selection and Automation Interface

## Context

We require a test harness that boots the ROM, injects joypad inputs, and verifies emulation state (e.g. coordinates, level state, collisions) headlessly inside a Linux container for local development and CI/CD validation.

## Decision

We select **SameBoy** as the primary emulator for automated testing, and **binjgb** as the secondary compatibility emulator.

Implementation details:
1. **SameBoy**: We build the C headless tool `sameboy_tester` and the shared library `libsameboy.so` from SameBoy source. Our Python test runner will load `libsameboy.so` via `ctypes` to run the game, inject inputs, read/write memory directly, and capture screenshots.
2. **binjgb**: We build `binjgb-tester` to execute basic smoke tests (ensure the ROM boots, runs for 100 frames, and dumps a correct visual screen).
3. **Symbol Table Parsing**: The Python test runner parses the `.sym` map file generated by the RGBDS linker at compile time. This allows the test script to read variables like `wPlayerX` and `wGameState` by name by translating them to their absolute memory addresses.

## Status

Accepted.

## Consequences

* Tests do not rely on GUI window managers (X11 or Wayland), making them fast and suitable for headless GitHub Actions runner environments.
* The test execution is 100% deterministic since we control the exact frame steps and input injections.
